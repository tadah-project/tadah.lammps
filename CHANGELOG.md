# Changelog

All notable changes to **Tadah.LAMMPS** (the `pair_tadah` LAMMPS pair-style integration) are documented here.
Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- Tests: `tadah.lammps_headers` (`ctest -L headers`, cmake-tools' `tadah_add_header_check`) compiles every header of `include/` on its own and twice in a row, with what a user of `tadah.lammps` gets. Both headers pass; the `ML-TADAH` pair-style sources are not checked.

## [1.6.0] — 2026-09-25

### Added
- `PairTadah::stage_extern(std::shared_ptr<tadah::LammpsTadah>)` / `clear_staged_extern()`: per-thread staging slot for the `EXTERN` potential handoff. Drivers that execute whole scripts through LAMMPS's `input->file()` (where per-line `load()` interleaving is impossible) stage the candidate potential once before the run; every `pair_coeff * * EXTERN ...` the script executes adopts it in `coeff()`. The slot lives outside the Pair object, so it survives `clear` cycles; precedence in `coeff()` is staged slot, then a pre-loaded `lt` (the 1.4.0 per-line driver pattern, unchanged), then a hard error.

### Changed
- `TADAH_LAMMPS_PAIR_STYLES` is **deprecated and ignored** — styles are discovered from the `PairStyle(...)` markers in the ML-TADAH headers. Setting it to a non-default value warns.
- Framework version `1.6.0`, read from CORE's `blueprint/blueprint_tadah.toml` after the Tadah dependencies are fetched, so the module reports the right version in every layout (sibling checkout or FetchContent). A missing blueprint is now a configure error instead of a silent `0.0.0`.
- Tests take Catch2 and its test discovery from cmake-tools (`tadah_setup_tests()`, `include(Catch)`); the vendored `tests/catch2/catch.hpp`, `tests/Catch.cmake` and `tests/CatchAddTests.cmake` are removed. Every discovered CTest entry now selects exactly its own test case and passes `--warn NoTests`, so an entry that matches no test case fails instead of passing. New test sources are picked up without a manual re-configure (`CONFIGURE_DEPENDS`).
- cmake-tools is fetched at `v1-dev` instead of `main`.
- **The `EAMFAST` load-time log line states where the collapse tables are accurate.** For the docs quickstart potential it reads `Tadah! pair-collapse fast path ON (2b-only, nr=8192): table certified for r in [2.80125, 6.5] (rel tol 1e-9: energy 3e-13, force 1e-9); analytic below r=2.80125`; an EAM-form model reports a `phi` and a `rho` table. It printed `parity dphi=3.071e+42`: the largest absolute value error at about 64 segment midpoints, with no range, no force check and no threshold, dominated by the extrapolated head of the table. In `eam_collapse.h`, `TableCertificate` (`phi_cert`, `rho_cert`) replaces `parity_err_phi` / `parity_err_rho`, and `certify_table()`, `check_segment()` / `SegmentCheck`, `sample_table()`, `phi_analytic()`, `collapse_phi()` / `collapse_rho()`, `format_collapse_report()`, `kCollapseNR` (8192) and `kCollapseCheckIntervals` (32) are new. A table that misses the tolerance already in its top segment, just below the cutoff, has no certified range; the log then says so (`collapse fast path unavailable: phi table misses rel tol 1e-9 already in its top segment, just below the cutoff r=…; using the generic kernel`, or `rho table …`) and the generic kernel is used.
- **`pair_style tadah` refuses a `DIMER` potential whose descriptors name specific element pairs.** `compute_dimers` evaluates every atom as Z=1, whatever its element (with the pair weight of Z=1, not the `WATOM` weight of the element), so a `TYPE2B`/`TYPEMB` declared for `N N` applied to no pair and the model predicted from zero descriptors without a word. `LammpsTadah` now calls `models::require_dimer_element_pairs()` (MODELS 1.6.0) when it is built, so `pair_coeff` fails (`PairTadah::load` prints `DIMER evaluates every atom as Z=1; declare TYPE2B/TYPEMB with * * element pairs` and the line); declare the descriptors with `* *`. Test: `test_dimer_element_pairs.cpp` (the published Tadah!N2 loads; `N N` and `* N` variants are refused).
- The README badges and links and the pointers to the umbrella's community files (`CITATION.md`, `CONTRIBUTING.md`, …) point to the `v1-dev` line: GitLab `v1-dev`, `https://tadah.readthedocs.io/v1-dev/`. They pointed to `develop`.
- `pair_coeff` prints the DM_REAM embedding reference (`EMBF0 ZERO` = F(0) = 0 by construction, the new default; `EMBF0 FREE` = raw 1.5.0 embedding). The EAMFAST kernel needs no change: F comes from `DM_Base::eam_embed`, which applies the reference. Rebuild required (DM_Base/DM_REAM layout). New DM_REAM collapse tests (Blip5 and negative-knot Knot5 fixtures): `eam_embed` equals w·calc_aed, F(0) == 0.0 under ZERO.
- **BREAKING (via Tadah.MODELS) — a DM_REAM potential must declare its density form, `RHOFORM SIGNED | NONNEG | MONOTONE`.** `pair_coeff` refuses a DM_REAM potential without the key, and the LAMMPS error now carries the reason: `pair_coeff: failed to load Tadah potential from '<file>': DM_REAM: RHOFORM is required: ...` (screen, `log.lammps`, and the exception a library driver catches). Previously the error named only the file and the reason of any load failure went to stderr alone. A `pair_coeff * * EXTERN` line with nothing to adopt (no staged potential, and the driver's own `load()` of this pair style failed) appends the same reason: `pair_coeff * * EXTERN: no staged or pre-loaded Tadah potential (last load() failed: <reason>)`. `PairTadah` keeps the reason of the last failed load (`last_load_error()`, set by all four `load` overloads); the command-line overload that `pair_coeff` uses no longer prints it to stderr. **Migration:** add `RHOFORM SIGNED` to a DM_REAM potential written before tadah 1.6.0 (bit-identical).
- `pair_coeff` prints the density form next to the EMBF0 banner: `Tadah! DM_REAM density form RHOFORM <form>` with `(signed amplitudes, the density before tadah 1.6.0)`, `(rho >= 0 by construction)` or `(rho >= 0 and non-increasing by construction)`. The EAMFAST kernel needs no change: its rho table is sampled from, and certified against, `DM_Base::eam_density`, which evaluates the declared form, and below the certified range the kernel calls `eam_density` itself. **Rebuild required**: the DM_REAM layout changed (Tadah.MODELS), and `PairTadah` gains a member (declared last, so the offset of `lt` is unchanged). Tests: `test_eam_collapse.cpp` (the `MONOTONE` collapse: the rho table follows `eam_density` to a relative tolerance and is certified over its whole range; a potential without `RHOFORM` fails to load with the migration text, and an invalid value is an error at its line of the file); every DM_REAM test potential declares `RHOFORM SIGNED`; the collapse test `eam_embed equals w.calc_aed; EMBF0 ZERO gives F(0)=0` is renamed `eam_embed equals w.calc_aed, EMBF0 ZERO gives F(0)=0`.

### Fixed
- **A non-linear potential that does not fit its descriptor is refused when it is loaded** (`pair_coeff`), naming the keys: KRR basis vectors whose length is not the descriptor's (`BASIS holds SBASIS 2 basis vectors of 4 values each, but the descriptor of the potential has 3 components`; every K(b, x) read past the shorter vector); through MODELS' `M_KRR_Core`, `WEIGHTS` without `SBASIS`/`BASIS` (the model predicted E = 0 for every atom) or with a number of weights other than the basis vectors, and a `BASIS` that `SBASIS` does not divide; and a `BF_Polynomial2` potential without D(D+1)/2 `WEIGHTS` for its D descriptor components (with fewer, every energy read past them; with more, the extra ones were ignored). Potentials of non-linear models trained with tadah 1.6.0 (MLIP) load, and `pair_style tadah` evaluates them as `tadah predict` does (HPO's `test_pair_tadah_nonlinear.cpp`: `BIAS false`, and `BIAS true` on one species), except a potential trained with `BIAS true` on several species: tadah (MLIP) trains it with one bias component shared by the species, while the descriptor of `pair_style tadah` has one per species, so such a potential (a kernel's or `BF_Polynomial2`'s) is refused with a message naming that cause (`BIAS true and 2 species`, the two descriptor sizes; a potential trained with `BIAS false` runs). Test: `test_krr_basis_load.cpp`.
- **`pair_style tadah` with `BIAS true` sets the bias component for the atoms LAMMPS has, local and ghost** (`compute_2b_mb_full`, which every non-linear model takes, and `compute_2b_mb_half`, which a linear many-body model takes). The loops ran over every column of the descriptor array, `atom->nmax` of them, and read `atom->type` past the atoms, where LAMMPS does not set it: in a fresh process each such column got a 1, written through an index read from before the per-type table, and `run 0` in a second LAMMPS instance of the same process (as `tadah hpo` creates for `PC_LAMMPS` evaluations) died with SIGSEGV. LAMMPS must be rebuilt. Test: HPO's `test_pair_tadah_nonlinear.cpp` (`pair_style tadah with BIAS true evaluates a trained model as the model predicts in every LAMMPS instance of a process`).
- **The `EAMFAST` fast kernels agree with the generic kernel to 1e-9 inside the certified range and exactly below it.** At load, each table is compared with the analytic function it samples, segment by segment from the cutoff down, and certified down to the smallest node `r_lo` above which every segment meets a relative tolerance of 1e-9 for the value and the derivative (energy and force). The errors are relative to the floor max(max|f| on [rc/2, rc], max|f| above the segment), so zero crossings and tapered cutoffs are handled and the scheme is unit-free. Each segment is sampled at 31 interior points, and its error between them is bounded by extrapolating from the neighbouring samples with a curvature allowance, because next to a C² knot (Blip bases, `KDEG` 3 knots) or the inner radius of `Cut_PolyS` / `Cut_CosS` the error peaks in a narrow band that a few check points per segment miss (three points understate it up to 3.5 times). The bound assumes the function is smooth on the scale of dr/32 apart from isolated knots and junctions, and it can exceed the true error, by up to 2 times next to a knot. `compute_2b_fast` and `compute_2b_mb_half_eamfast` evaluate the pair term analytically below `r_lo` (`phi_analytic()`, which also builds the table nodes, and the descriptor's `eam_density()` for `rho`). They used the table at every distance: for the quickstart potential its value was off by a factor of 130 at 1.2·10⁻³ Å and by 1.6·10⁻⁶ in the force at 0.1 Å. The certified range of the quickstart potential starts at 2.80 Å, below its bcc nearest-neighbour distance of 3.03 Å; closer in, the r⁻¹² term changes too quickly for a table of 8192 points to give the force to 1e-9 of the force scale near the minimum of the pair energy (2.68 Å). The certified range is one interval ending at the cutoff, so a single failing segment (a Blip knot, a switching-cutoff junction) ends it, and closer pairs cost as much as in the generic kernel. In 250-atom MD runs the fast path is 1.6 times (quickstart D2_LJ), 3.4 times (D2_LJ + DM_REAM) and 4.5 times (21-knot D2_Knot5) faster than the generic kernel.
- **`pair_style tadah` stops on two atoms at the same position**, naming their atom IDs (`error->one`: `pair_tadah: atom IDs 1 and 3 are at the same position ...`), in every kernel (`compute_dimers` of a `DIMER` potential included) and in `single()`; every force was nan (`run 0` completed with NaN forces, and dynamics carried on). LAMMPS must be rebuilt.
- **Pairs in the top table segment, just below a `Cut_Dummy` cutoff, got forces of order |phi(rc⁻)|/dr** (fmax 20.8 instead of 1.4 eV/Å on a rattled bcc cell with the quickstart potential, and the same in `compute_2b_mb_half_eamfast`). `Cut_Dummy` is 0 at rc, and the top table node was sampled there, which pulled the whole segment [rc − dr, rc) towards 0. The top node now holds the limit from below; this also covers cutoffs for which (nr − 1)·dr rounds above rc. `compute_2b_fast` skips a pair at exactly rc, where the cutoff is 0, as the EAM kernel does.
- **ML-TADAH now builds against LAMMPS with the runtime style registry (LAMMPS >= 2 Jun 2026).** LAMMPS commit `7ee0259e` ("style registry: stop generating the now-unused `style_*.h` and `packages_*.h`") moved pair/fix/compute styles from a compile-time `#include` list to a runtime registry: `styles/style_pair.h` is gone, and `GenerateStyleSources` now emits `styles/style_pair.cpp` which calls `Force::pair_styles().add_builtin(...)`. The integration hook appended `#include "pair_tadah.h"` to that header and hard-errored when it was missing, so **every configure against a LAMMPS newer than 2 Jun 2026 failed** with `ML-TADAH: Cannot find generated file: <build>/styles/style_pair.h`. Worse is the near miss: a LAMMPS configured *without* the hook links and starts perfectly, and only fails at run time with `ERROR: Unrecognized pair style 'tadah'` — which under `tadah hpo` surfaces as 100 % band-B "script failed" and no cause at all, because `LammpsSim` opens LAMMPS with `-screen none -log none`.
  The hook now calls LAMMPS's own `RegisterStyles()` on the `ML-TADAH` directory instead of patching a generated file. Both LAMMPS generations read the same global style properties, so one mechanism covers both, LAMMPS discovers the styles from the `PairStyle(...)` markers in our headers (no per-style bookkeeping here), and any style category we add later works without further changes. Verified end to end on **both** LAMMPS `2 Sep 2026` (generates `style_pair.cpp` with `add_builtin("tadah", &creator<PairTadah>)`) and `11 Feb 2026` (generates `style_pair.h` with `#include "pair_tadah.h"`): each configures, builds, lists `tadah` in `lmp -h`, and reaches `PairTadah::coeff()` on `pair_coeff * * EXTERN`.
  Timing is the subtle part and is commented in the hook: registration must happen after `include(StyleHeaderUtils)` defines `RegisterStyles` but before the generators consume the properties. `CMAKE_PROJECT_INCLUDE` runs hundreds of lines too early and `cmake_language(DEFER)` runs too late, so the hook watches `LAMMPS_STYLE_HEADERS_DIR`, which LAMMPS sets on the line immediately before those generators in both generations.
- **A configure-time assertion that the pair style was actually registered.** After LAMMPS finishes, the hook checks that a generated `style_pair.cpp`/`style_pair.h` really names `pair_tadah.h`, and hard-errors otherwise. A future LAMMPS reshuffle now stops the build instead of silently producing a binary that rejects `pair_style tadah` at run time.
- `pair_coeff * * EXTERN` with no staged or pre-loaded potential, and `pair_coeff` with an unloadable potential file, now raise a clean LAMMPS error. Previously `coeff()` discarded `load()`'s failure return and dereferenced the null potential — a segfault (this is how the legacy `input->file()`-based MPI worker died on EXTERN scripts).
- Test fixture `valid_config5` (the `M_BLR_MD`/`M_KRR_MD` constructor tests) is valid under the current grammar: it declared a bare `TYPE2B D2_Blip`, which fails since 1.6.0 when the descriptors are built, used the pre-1.x grid codes `-1`/`-2` (now `LIN`/`GEOM`) and had no `ATOM` for its intercept column. A new test builds its descriptors and checks their columns against the weights.
- `README.md` and `integration/README.md` said `TADAH_GIT_BRANCH` selects the Tadah.LAMMPS branch and defaults to `main`. It is the git ref the Tadah modules are fetched at (Tadah.MD and, through it, MODELS and CORE); the Tadah.LAMMPS sources are the checkout at `TADAH_LAMMPS_SOURCE_DIR`. Without it the ref is detected from the checkout of the project CMake was started on, which in the LAMMPS build is LAMMPS (`stable`, `develop`, ...), so the READMEs now pass it (`-DTADAH_GIT_BRANCH=v1-dev`, or a release tag such as `v1.6.0`), in every configure example, and describe the detection. They clone Tadah.LAMMPS at `v1-dev` or a release tag by name (`git clone -b`): a plain clone checks out the repository's default branch. An example used a personal path.
- **`pair_coeff` now warns when a DM_REAM potential has no `EMBF0` line (BUG-08).** Such a potential is evaluated with the default `EMBF0 ZERO` (F(0) = 0 by construction), which moves every atomic energy of a potential written by tadah 1.5.0 or earlier by -F(0) (for a non-linear model, forces change too). Previously LAMMPS printed only the same neutral banner as for an explicit `EMBF0 ZERO`. The tadah notice meant for this case never showed up in LAMMPS: the tadah Logger defaults to ERROR and writes only to std::cout. Now every `pair_coeff` that loads such a potential prints a LAMMPS `WARNING`, on screen and in log.lammps, with the same text as the tadah notice, and the banner reads `EMBF0 ZERO (key absent: default ZERO, ...; add EMBF0 FREE to reproduce tadah <= 1.5.0 energies)`. Potentials that declare `EMBF0` print exactly what they printed before. Evaluation does not change. `LammpsTadah::embf0_declared` records whether the potential context as given stored the key, before DM_REAM materialises the default. **Rebuild required**: the `LammpsTadah` layout changed, and Tadah.HPO includes it.
- `pair_coeff` reports a failure of `LammpsTadah::initialize()` through `error->all` with its reason: `pair_coeff * * pot.tadah W` for an element the potential does not have stops with `ERROR: pair_coeff: failed to initialise Tadah potential 'pot.tadah': Symbol not in potential file: W` on the screen and in `log.lammps`, and in the exception a library driver catches. The exception escaped `coeff()`, so LAMMPS' `main` printed it to stderr and `log.lammps` recorded nothing. The `load(Context)` overloads no longer print a failure to stderr: `pair_coeff * * EXTERN` reports `last_load_error()` through `error->all`, so the reason appeared twice. Tests: `test_eam_collapse.cpp` (the reason `initialize()` gives), and through LAMMPS HPO's `test_ream_fastpath.cpp` (this module's tests have no LAMMPS instance).

## [1.4.0] — 2026-07-14

### Added
- **EAM-collapse fast path** (`compute_2b_mb_half_eamfast`, new header `eam_collapse.h`): for a linear model whose descriptors are a radial two-body block plus an EAM-form many-body block, single species (the `tadah refit` family, e.g. `D2_Knot5` + `DM_REAM`), the potential collapses exactly to scalar pair/density/embedding functions. The pair style evaluates cubic-Hermite `phi`/`rho` tables sampled from the descriptors' own calc routines plus the analytic embedding, with scalar (1-double) ghost communication instead of descriptor-vector comm. ~7x faster force calls on the refit family; agrees with the generic kernel to ~1e-9 relative (a mid-node parity self-check is logged at load). Controlled by the `EAMFAST` config key, **default on**; set `EAMFAST false` in the potential/config for the bitwise generic path. Non-collapsible models (nonlinear, normalised, bias, multi-species, dimer, non-EAM-form MB) silently keep the generic kernel. Adjoint capture (`capture_adjoint_state`) with the fast path active is a hard error — such drivers must set `EAMFAST false`.
- `PairTadah::load(std::shared_ptr<tadah::LammpsTadah>)`: drivers (e.g. `tadah hpo`) can build ONE potential object per candidate and share it across `clear`/`pair_coeff EXTERN` cycles instead of reconstructing it per `pair_coeff`. The object carries per-simulation scratch, so sharing is valid only across sims that run sequentially (per-thread).

### Changed
- `PairTadah::lt` is now a `std::shared_ptr` (was `unique_ptr`); all existing `load` overloads keep their semantics.

## [1.3.0-beta.1] — 2026-05-20

A small but focused release: a per-species bias precomputation, the `i`/`j` swap fix, and the standard build / community / VERSION wiring.

### Added
- Version banner — `pair_tadah` now prints the Tadah! VERSION (read from the blueprint TOML at build time) from `PairTadah::coeff()` so that LAMMPS log files record exactly which version produced the run.
- `TADAH_ENABLE_ASAN` build option.

### Changed
- Per-species bias lookup precomputed at `initialize()` (instead of recomputed per call) — small but measurable per-step speed-up in LAMMPS runs that use the per-species intercept layout.

### Fixed
- Pair indexing: `i` / `j` swap corrected.

### Internal
- Community / governance pointer files added (umbrella canonical at `Tadah.MLIP/`).
- VERSION single-source-of-truth wired from blueprint TOML.
- CI: lint stage and tag-gated release-tarball stage added.
- Test build routed through `cmake-tools/cmake/TadahTesting.cmake` helpers (`tadah_declare_testing` / `tadah_add_tests`).

## [1.1.1] and earlier (condensed)

The `v1.0.0` → `v1.1.1` releases were the "internal playground" era. The LAMMPS pair-style integration matured during this period: CMake-driven LAMMPS build, integration tests, ghost-atom NN-list correctness fixes, and `D2_mJoin` / `compute_2b` wiring. `v1.1.1` was the last tag in this era and is the version on which downstream LAMMPS users have been running until this beta. No published changelog covers this era; treat anything before `1.3.0-beta.1` as undocumented in the modern sense.

> Note: Tadah.LAMMPS uses its own per-repo tag history (`v1.0.0`, `v1.1.1`); from `1.3.0-beta.1` onward it tracks the umbrella version.
